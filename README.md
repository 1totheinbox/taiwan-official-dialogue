# taiwan-official-dialogue：臺灣公文對話模擬器

讓 AI 助理用臺灣公文的形式和你對話的技能（Agent Skill）。每一輪：

1. 先把你說的話改寫成一份最高機關（根目錄版叫「最高樞密院」）發給 AI 所屬機關的完整函稿（來文）。
2. 再以該機關的名義，用另一份完整函稿答復（復文）。
3. 表格、程式碼、圖片等非純文字內容，統一列在文末的附件區。
4. 機關之間的簡短聯繫，以及工具作業中的進度通知，另以便簽呈現。

AI 仍會實際回答問題、執行任務，只是輸出的外框是公文。用語依行政院《文書處理手冊》（112 年 6 月 8 日修正）及文書處理相關釋例整理。

這是對話用的模擬，不是正式發文。機關名稱與人名均為虛構；發文字號、檔號、保存年限及便簽的格式是本技能自訂的編法，不是手冊規定。

## 檔案

| 檔案 | 用途 | 何時讀取 |
|---|---|---|
| `SKILL.md` | 技能本體：外框、欄位、角色、來文與復文的寫法、示例 | 啟用時 |
| `references/agencies.md` | 機關對照表：AI 是哪個機關、對誰用什麼稱謂 | 啟用時 |
| `references/writing-rules.md` | 撰寫細則：用語、用字、數字、標點、欄位 | 啟用時 |
| `references/general-guide.md` | 正式公文的通用規則與用語使用時機指南 | 需要時才讀 |
| `agents/openai.yaml` | Codex 介面顯示的名稱與預設提示 | 只有 Codex 使用 |

## 安裝

把整個資料夾放進你所用工具的技能資料夾，資料夾名稱維持 `taiwan-official-dialogue`。

Claude Code：

```bash
git clone https://github.com/1totheinbox/taiwan-official-dialogue ~/.claude/skills/taiwan-official-dialogue
```

Codex：

```bash
git clone https://github.com/1totheinbox/taiwan-official-dialogue ~/.codex/skills/taiwan-official-dialogue
```

Gemini CLI、Antigravity 及其他支援 Agent Skills 的工具：放進該工具的技能資料夾，位置依工具及版本而異，請查該工具的文件。

安裝後對 AI 說「請用臺灣公文形式跟我對話」即可啟用；說「恢復一般對話」停用；說「簡式」只留主旨、說明、辦法。

## 平臺專用版

根目錄的跨平臺版，機關表是照原作者的多 agent 配置寫的。只用單一工具、沒有這種配置的人，改裝 `platforms/` 底下的專用版：機關依該工具內部的模型劃分，一個模型一個機關，等級最高的模型是總署，其餘是執行機關；不預設任何人名，安裝後第一次啟用會先帶你設定內部機關。

| 工具 | 資料夾 | 預設的內部機關 |
|---|---|---|
| Claude Code | `platforms/claude-code/taiwan-official-dialogue-claude-code` | Opus＝綜合規劃總署；Sonnet＝事務執行局；Haiku＝庶務工作站 |
| Codex | `platforms/codex/taiwan-official-dialogue-codex` | gpt-6.1-sol＝綜合規劃總署、事務調度處、審查稽核處、圖像製作中心；gpt-6.1-terra＝資訊工程局、電腦操作中心；gpt-6-luna＝事務所 |

安裝：把上表的資料夾整個複製到該工具的技能資料夾，資料夾名稱不要改。

首次啟用時，AI 會先盤點工具裡實際可用的模型，依預設值擬一份機關表請你確認或修改（各模型對應的機關名稱、字別、首長職銜；姓名選填），寫回 `references/agencies.md` 後才開始以公文對話。說「用預設」可直接採用預設值，之後說「重新設定機關」可以重來。

對話當下用哪個模型，就由那個模型的機關發復文；派出的子代理用哪個模型執行，就是哪個機關。Codex 版同一個模型對應多個機關，預設由該模型的預設機關承辦，任務屬於其他機關的職掌時改由該機關承辦。

兩個專用版由 `scripts/build_platforms.py` 從根目錄的檔案產生；根目錄的內容有修改時重跑這支腳本即可同步。

## 不同家 AI 安裝後的差異

以下是對檔案內容做的靜態檢查，沒有在每一家工具裡逐一實測。

各家相同的部分：

- `SKILL.md` 的前置資料只有 `name` 和 `description` 兩欄，沒有任何單一廠商專用的欄位；`description` 為 197 字。
- 所有檔案是 UTF-8、無 BOM、LF 換行；參考檔以相對路徑連結。
- `SKILL.md` 與 `references/` 的內文沒有寫死任何一家工具的指令語法或工具名稱。

會有差異的部分：

| 項目 | 差異 |
|---|---|
| `agents/openai.yaml` | 只有 Codex 會讀，用來顯示名稱與預設提示；其他工具會忽略，不影響行為。 |
| 啟用方式 | 各家叫用技能的語法不同（例如 Claude Code 用 `/taiwan-official-dialogue`，Codex 用 `$taiwan-official-dialogue`）；用自然語言要求「以臺灣公文形式對話」則各家都能觸發。 |
| AI 是哪個機關 | 依 agent 的配置名稱對照 `references/agencies.md`。表內區名對應模型：西區為 Claude、東區為 GPT、南區為 Gemini，所以同一句話在不同家會由不同機關署名。配置名稱對不上表時，一律寫成「承辦機關」。 |
| 發文字號的時間 | 14 碼字號含當下的日期時間。能取得系統時間的工具會填實際時間；不能取得的部分會以「○」保留。 |
| 進度便簽 | 只有在工具作業中途會輸出文字的介面才會出現；一次回完的介面不會有。 |
| 欄位換行 | 函稿欄位靠 Markdown 行尾兩個空格換行；不渲染 Markdown 的介面會看到欄位擠在一起或多出空格。 |
| 指南的讀取 | `references/general-guide.md` 篇幅長，設計成需要時才讀。會把技能資料夾一次全部載入的工具，會多佔一些上下文。 |

## 改成你自己的機關

`references/agencies.md` 是照原作者的多 agent 配置寫的。你沒有相同配置時，技能仍可使用，只是 AI 會自稱「承辦機關」。要換成自己的設定，改這個檔案的兩處：

1. 「最高機關」一節：把函頭名稱、署名（職銜　姓名）、字別換成你要的，例如：

   ```
   - 使用者是唯一的最高機關，銜稱定為「總管理處」，函頭、受文者及正本寫「總管理處」，署名寫「處長　○○○」，函內自稱「本處」，發文字號用「總管字」。
   ```

2. 對照表：每個 agent 一列，沒有多個 agent 時留一列即可：

   ```
   | 配置名稱 | 機關名稱 | 署名（職銜　姓名） | 字別 | 自稱 | 類別 | 模型 |
   |---|---|---|---|---|---|---|
   | 綜合規劃署 署長 ○○○ | 綜合規劃署 | 署長　○○○ | 綜規 | 本署 | 派工 | （你用的模型） |
   ```

改了最高機關的名稱後，`SKILL.md` 與 `references/writing-rules.md` 裡的「最高樞密院」「總執　仲瑿」「鈞院」也要一併取代。根目錄版另有一項自訂：最高樞密院在設定中地位類比總統，各機關對它上行用「檢呈」而不是「檢陳」；不需要這項設定時，把兩個檔案裡的「檢呈」改回「檢陳」，或直接改用平臺專用版（專用版一律用「檢陳」）。機關名稱請用虛構的，不要冒用真實機關。

## 規範依據

- 《公文程式條例》
- 行政院《文書處理手冊》（112 年 6 月 8 日修正）及其附錄
- 行政院「文書處理相關釋例」
- 國家文官學院《公文撰作解析》

`references/general-guide.md` 文末列有完整來源；其中部分釋例取自二手轉引，正式送件前請回到官方來源查證。
